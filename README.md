# loadit. — 로드잇

**일반 다운로드 + 다중 페이지 단일 HTML 웹사이트 보존 + 빠른 메모 저장**을 하나의 Chrome 확장프로그램으로 통합합니다.

## 무엇을 만들었나

| 기능 | 동작 |
| --- | --- |
| 범용 다운로드 | 파일 URL 입력, 브라우저 기본 다운로드 API 사용, 링크/이미지/미디어 우클릭 다운로드 |
| 파일 탐색 | 현재 페이지의 다운로드 링크 및 이미지/미디어 URL 수집 후 선택 다운로드 (최대 30개/회) |
| 다운로드 관리 | 최근 다운로드 확인, 일시정지/재개/취소/파일 보기 (Chrome에서 허용하는 작업만) |
| 빠른 로컬 저장 | 메모 및 드래그 선택 텍스트를 로컬 `.txt`로 저장 |
| GitHub 빠른 저장 | 사용자가 직접 입력한 텍스트를 지정 저장소에 새 파일로 생성 (선택 기능) |
| 다중 페이지 아카이브 | 시작 페이지 및 같은 출처의 링크를 최대 12페이지/3단계까지 수집 |
| **한 개의 HTML** | **HTML/CSS/이미지/글꼴과 다중 페이지 캡처를 하나의 HTML에 내장해 JS로 페이지 전환** |
| 오프라인 뷰어 | 파일을 로컬로 열어 사이드바 검색·앞/뒤 페이지·내부 링크를 JS로 제어 |\n| CDP 네트워크 기록 | Chrome 디버거로 페이지 로딩 시 HTTP(S) 응답 본문·요청 메서드·WebSocket 송수신 프레임을 제한적으로 수집 |\n| 실험적 원본 JS 재생 | 기본 정적 보존, 사용자가 선택하면 기록된 fetch/XHR 응답과 WebSocket 프레임을 재생 |

**제약:** 실행 소스는 **HTML, CSS, JavaScript만** 사용합니다. 프레임워크/Node.js/백엔드/빌드 도구/외부 CDN/GitHub Actions 없음. 크롬 확장프로그램에는 브라우저가 요구하는 `manifest.json` 설정 파일이 필수입니다. `README.md`는 설명 문서입니다.

## 설치

1. 이 저장소의 파일을 ZIP으로 내려받고 압축을 풉니다.
2. Chrome의 `chrome://extensions`로 이동해 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다** → `manifest.json`이 있는 최상위 폴더를 선택합니다.
4. 툴바에 나타난 **Loadit** 아이콘을 클릭합니다.

별도의 서버 설치나 npm 명령은 필요 없습니다.

## 사용법

### 1. 어떤 파일이든 다운로드

- **다운로드** 탭에 HTTP(S) 파일 URL을 붙여넣고 다운로드합니다.
- 웹사이트에서 링크·이미지·영상·오디오를 **우클릭 → Loadit 다운로드**합니다.
- **파일 탐색**을 누르면 현재 페이지의 정적 링크/이미지/미디어 후보가 나옵니다.
- 다운로드 현황에서 **정지/계속/취소/보기**를 수행할 수 있습니다.

브라우저가 접근할 수 없는 리소스, DRM 콘텐츠, 로그인/세션 보호가 필요한 URL, 일회성 요청/특정 헤더가 필요한 다운로드 등은 실패할 수 있습니다. 다운로드 가속·분할 스트리밍 엔진을 별도로 구현한 것은 아닙니다.

### 2. SingleFile 고급형: 다중 페이지 → 하나의 HTML

1. **사이트 보존** 탭에 시작 URL을 입력합니다.
2. **최대 페이지**(1~12)와 **링크 깊이**(0~3)를 설정합니다.
3. 웹사이트 접근 권한을 승인하고 **단일 HTML 만들기**를 누릅니다.
4. 결과물은 Chrome 다운로드 폴더의 `Loadit/<도메인>-<날짜>.html`입니다.
5. 저장된 HTML을 Chrome/Edge/Firefox 등에서 로컬로 열고, 왼쪽 메뉴에서 페이지를 전환합니다.

저장 결과는 **외부 CSS·JavaScript에 의존하지 않는 1개의 HTML**입니다. 각 페이지의 렌더링 DOM과 가능한 정적 자산을 기본 보존하며, 원본 JS 소스와 CDP로 수집된 네트워크 응답도 한 HTML 안에 담습니다. 뷰어는 JS로 페이지를 전환합니다.\n\n**[원본 JS 재생 (실험)]** 체크박스를 켜면 iframe 샌드박스에서 원본 스크립트를 다시 실행하고, 저장된 fetch/XHR 응답과 WebSocket 프레임을 로컬로 공급합니다. 기록되지 않은 요청은 차단합니다. 페이지에 따라 재실행 후 DOM이 달라지거나 작동하지 않을 수 있으므로 기본값은 꺼짐입니다.

**정확한 보존 범위와 제한**

- 캡처: HTML DOM, 폼의 일반 입력값, 인라인 CSS, 다운로드 가능한 스타일시트/배경/이미지/글꼴, 크기 제한 내 미디어, 읽을 수 있는 캔버스 이미지.
- 탐색: 같은 **origin**의 HTTP(S) 링크. 외부 도메인은 자동 방문하지 않습니다.
- 일부 CSS/CDN·이미지 리소스는 CORS/접근권한/로그인/용량 제한으로 담기지 않을 수 있습니다. 실패 건수는 확장 상태에 표시됩니다.
- Chrome 디버거를 통해 새 임시 탭을 방문해 **HTTP 요청/응답, WebSocket 프레임을 캡처**합니다. 브라우저 자체가 보여 주는 디버거 연결 경고가 발생할 수 있습니다.\n- **원본 JS 재실행 / fetch / XHR / WebSocket 리플레이는 실험 기능입니다.** 브라우저에 이미 수신한 API 응답·메시지의 일부를 저장하고 재생하는 방식으로, 새로운 서버 연산이나 실시간 데이터를 생성하지는 못합니다.\n- 원본 페이지의 외부 JS를 모두 담지 못할 수 있으며 `Service Worker`, 모든 iframe, `IndexedDB`, 모든 `localStorage` 상태를 완전 복제하지 않습니다. `type=module`의 외부 import, CSP, 로그인 상태에 의존하는 코드 또한 제한됩니다.
- 서버 DB, DRM, 사이트의 실시간 내부 상태, 로그인 인증/쿠키, 원본 서버 로직을 복제할 수 없습니다.
- 사용자의 비밀번호·숨겨진 폼 값·쿠키·localStorage·인증 헤더·요청 본문은 추출하지 않습니다.
- 오프라인 페이지는 `iframe sandbox`와 CSP로 원본 스크립트·폼 제출·네트워크 접근을 제한합니다.
- 암호화·서명·인터넷 없이 영구적인 완전 복원을 보증하는 도구는 아닙니다.

### 3. 메모 및 GitHub 빠른 저장

- 텍스트를 드래그해 우클릭하면 즉시 로컬 `.txt`로 내려받습니다. 마지막 선택 텍스트를 메모 탭에도 불러옵니다.
- **빠른 메모** 탭에서 로컬 파일로 저장하거나 **owner/repo**, 신규 파일 경로, **Contents: write** 권한을 가진 Fine-grained PAT를 입력해 GitHub에 저장합니다.
- GitHub 토큰은 저장하지 않으며, 전송된 후 메모리/입력란에서도 지웁니다. 저장소/경로(비밀 아님)만 Chrome storage에 기억할 수 있습니다.
- GitHub 저장은 기존 파일을 덮어쓰지 않고 **새 파일만 생성**합니다. GitHub 이외의 일반 파일 다운로드에는 PAT가 필요 없습니다.

## 로컬 검증 시나리오

`test-site/`를 HTTP(S)로 서비스하고 이 확장으로 아카이빙하세요. (예: 테스트 전용 로컬 웹서버 사용. 로컬 `file://` 주소는 아카이빙 대상에서 제외됨.)

1. [ ] 테스트 시작 페이지에서 동적 JS로 추가된 요소가 저장된 뷰어에서도 보이는지 확인
2. [ ] 내부 2페이지 링크를 클릭하면 **같은 HTML 파일 안**에서 페이지 전환되는지 확인
3. [ ] 네트워크를 끊은 상태로 위 파일을 열어도 스타일/내장 이미지/메뉴가 작동하는지 확인
4. [ ] 외부 사이트 링크는 저장된 페이지를 벗어나지 않고 안내를 표시하는지 확인
5. [ ] 암호 입력 및 `onload` / `onclick` 스크립트가 저장본에서 실행되지 않는지 확인
6. [ ] 파일 탐색/다중 다운로드/일시정지·재개·취소 확인
7. [ ] 선택 텍스트 로컬 저장 및 GitHub **새 파일** 생성 확인
8. [ ] 캡처에 실패한 자산이 있어도 부분 보존 경고가 표시되는지 확인\n9. [ ] DevTools Network 기록으로 XHR/fetch 응답과 WebSocket 메시지가 보존되는지 확인\n10. [ ] **원본 JS 재생 (실험)** 모드에서 기록된 응답이 공급되는지 확인\n11. [ ] 캡처 종료 후 디버거가 해제되고 임시 탭이 닫히는지 확인

**검증 표기:** 현재 소스 문법·구조 검증과 GitHub 저장 여부를 확인했지만, 사용자의 Chrome 확장 설치 및 실제 사이트별 end-to-end 테스트는 이 문서의 체크리스트대로 별도 검증이 필요합니다. 특정 페이지의 완전 복원은 보장하지 않습니다.

## 원칙

- 기본적으로 모든 수집은 사용자가 명시한 작업에서만 시작됩니다.
- 자동 아카이빙은 같은 출처로 제한하고, 페이지 수·자산 크기·기록 응답 크기를 제한합니다. 다중 페이지 결과는 약 75MiB 내로 제한합니다.
- 민감 데이터를 자동으로 수집·업로드하지 않습니다.
- 사이트 약관과 허가 범위 안에서 사용하세요.
