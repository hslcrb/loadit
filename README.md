# Loadit · 로드잇

> **파일은 빠르게, 웹사이트는 오래.**  
> 일반 파일 다운로드, 선택한 텍스트의 빠른 저장, 여러 웹페이지의 단일 HTML 아카이빙을 **하나의 Chrome 확장프로그램**으로 묶은 프로젝트입니다.

[개발기 전체 보기](docs/DEVELOPMENT_LOG.ko.md) · [구현 커밋](https://github.com/hslcrb/loadit/commit/7042099b664d1a93ccf25ea87eb7e184063dbc58)

**현재 버전:** `0.2.0` · **개발 단계:** 초기 기능 구현 / 종단간 실사용 검증 이전 · **문서 기준일:** 2026-11-21 (KST)

Loadit은 두 가지 구상에서 출발했습니다. 하나는 **GitHub뿐 아니라 일반 웹 링크·이미지·미디어 파일까지 다루는 빠른 저장·다운로드 확장**이고, 다른 하나는 **SingleFile의 단일 페이지 한계를 넘어 여러 페이지를 한 HTML 파일에 담아 JavaScript로 이동하는 아카이버**입니다. 이 두 도구는 같은 확장 안의 독립된 작업 흐름이며, GitHub 계정이 없어도 다운로드와 아카이빙은 사용할 수 있도록 설계했습니다.

## 1. 기능과 현재 상태

| 모듈 | 현재 구현된 동작 | 반드시 알아둘 점 |
| --- | --- | --- |
| **Download** | HTTP(S) URL 다운로드, 링크·이미지·영상·오디오 우클릭 다운로드 | Chrome의 기본 `downloads` API 사용. 별도의 분할 가속 다운로드 엔진은 아님 |
| **Discovery** | 현재 페이지의 `a[href]`, `img`, `video`, `audio`, `source`에서 후보 URL 탐색 | 최대 180개 후보 수집, 한 번에 최대 30개 선택 다운로드. 숨겨진 모든 요청을 찾지는 못함 |
| **Download Manager** | Chrome 다운로드 기록 조회, 정지·재개·취소·파일 보기 | 각 동작의 가능 여부는 브라우저·서버가 결정 |
| **Quick Save** | 드래그 텍스트의 로컬 TXT 저장, 메모 작성 및 TXT 다운로드 | 웹페이지의 임의 파일을 GitHub로 자동 복제하는 범용 업로더는 아님 |
| **GitHub Save** | PAT를 입력해 저장소·폴더 조회 후 새 텍스트 파일 작성 | `Contents: write`가 필요한 별도의 선택 기능. 기존 파일 덮어쓰기 미지원 |
| **Site Archive** | 같은 출처의 링크를 따라 여러 페이지 수집 | 최대 12페이지, 깊이 0~3. 전체 사이트 무제한 복제 아님 |
| **Single HTML Viewer** | 수집한 DOM·일부 리소스를 하나의 `.html`에 내장하고 목록·내부 링크로 페이지 전환 | 외부 CSS/이미지/API/서버 기능이 완전히 재현된다는 보장은 없음 |
| **Network Capture** | Chrome Debugger/CDP로 수신된 HTTP 응답과 WebSocket 프레임 일부 기록 | 기록 범위·응답 크기·브라우저 지원의 제약 존재 |
| **Offline Replay** | 저장된 fetch/XHR 응답, WebSocket 수신 프레임을 공급하는 실험적 런타임 | **기본 비활성화**. 원본 JavaScript 호환성 및 실제 사이트 검증 미완료 |

**기술 스택 제약:** HTML, CSS, **바닐라 JavaScript**만 사용합니다. Chrome 확장 규격상 설정 파일인 `manifest.json`은 필수이므로 예외입니다. npm, React, TypeScript, Node.js 상주 서버, Playwright 상주 서버, 데이터베이스, 번들러, 외부 CDN 또는 GitHub Actions는 현재 실행 경로에 없습니다. GitHub에 파일을 저장하는 선택 기능은 GitHub 공식 REST API에 직접 요청합니다.

## 2. 설치

1. 이 저장소의 **Code → Download ZIP**으로 코드를 내려받거나 Git으로 복제합니다.
2. ZIP을 사용했다면 완전히 압축을 해제합니다. `manifest.json`이 폴더 최상위에 있어야 합니다.
3. Chrome 주소창에 `chrome://extensions`를 입력합니다.
4. 오른쪽 위의 **개발자 모드**를 켭니다.
5. **압축해제된 확장 프로그램을 로드합니다**를 누르고 Loadit 폴더를 선택합니다.
6. 확장 메뉴에서 **Loadit**을 고정하면 편리합니다.

이 프로젝트는 아직 Chrome Web Store 배포나 서명된 공식 릴리스를 제공하지 않습니다. 폴더를 로드했을 때 오류가 표시되면 확장 카드의 **오류**를 열고 [문제 해결](#9-제약과-알려진-문제)을 확인해 주세요. 새 코드를 받은 뒤에는 `chrome://extensions`에서 **새로고침**해야 기존 설치에 변경 사항이 적용됩니다.

## 3. 빠른 시작

### A. URL 파일 다운로드

**↓ 다운로드** 탭을 열고 HTTP(S) 파일 주소를 입력한 다음 **URL 다운로드**를 누릅니다. 저장 파일명을 비우면 브라우저·서버가 제공한 이름을 사용하고, 직접 쓰면 지정한 상대 경로·파일명으로 요청합니다.

### B. 웹페이지 안의 파일 고르기

원하는 웹사이트에서 Loadit 팝업을 열고 **파일 탐색**을 누릅니다. 탐지된 링크·이미지·미디어 중 원하는 항목에 체크하고 **선택한 파일 다운로드**를 누릅니다. 우클릭 메뉴로 링크/이미지/미디어 하나를 바로 받을 수도 있습니다.

### C. 여러 웹페이지를 HTML 하나로 보관

**▣ 사이트 보존** 탭에서 시작 주소와 페이지 수·탐색 깊이를 선택한 뒤 **단일 HTML 만들기**를 누릅니다. 브라우저가 요구하는 사이트 접근 허가를 승인하면 임시 탭에서 수집합니다. 저장된 HTML을 로컬로 열면 왼쪽 페이지 목록과 내부 링크로 이동할 수 있습니다.

### D. 글을 저장하기

텍스트를 드래그하고 **우클릭 → Loadit · 선택 텍스트 로컬 저장**을 선택하면 TXT를 내려받습니다. **GitHub 빠른 저장**을 선택하면 메모 화면을 열어 저장소·폴더를 지정할 수 있습니다. GitHub에 쓰려면 별도의 토큰이 필요합니다.

## 4. 다중 페이지 단일 HTML 아카이버

### 핵심 개념

웹사이트를 페이지별 HTML 여러 개로 흩어 놓지 않고, **하나의 HTML 파일에 여러 페이지 기록을 포함**합니다. 그 파일 자체가 탐색용 UI와 데이터를 지니고 있으며 사용자는 탭 전환처럼 서로 다른 페이지로 이동할 수 있습니다.

```text
시작 URL
   │
   ├─ 링크 수집 → 동일 출처 URL 큐 → 깊이/개수 제한
   │
   ├─ 임시 Chrome 탭 → CDP 네트워크 기록
   │                       ├─ HTTP 응답 본문(가능한 범위)
   │                       └─ WebSocket 프레임(가능한 범위)
   │
   ├─ 브라우저 DOM 스냅샷
   │       ├─ HTML + CSS
   │       ├─ 이미지·폰트·일부 미디어
   │       ├─ 스크립트 소스(실행되지 않는 기록)
   │       └─ 일반 폼 표현 상태
   │
   └─ viewer.html 템플릿 + 내장 JSON 데이터
                         │
                         ▼
              Loadit/<도메인>-<날짜>.html
                         │
                오프라인 열기 / JS 페이지 전환
```

**현재 설정값:** 최대 페이지 1·3·5·8·12개 중 선택, 탐색 깊이 0~3단계. 코드는 상한 12페이지와 총 HTML 데이터 크기 약 75MiB를 적용합니다. 페이지별 캡처 자산 예산은 기본 약 10MiB, 단일 자산은 그보다 작은 별도 제한이 있고, 네트워크 수집기에는 응답 및 세션별 용량 제한이 있습니다. 제한에 걸리면 일부 리소스가 빠지거나 수집이 조기 종료될 수 있습니다.

**탐색 범위는 같은 origin**입니다. 예를 들어 `https://example.com`에서 시작한 경우 `https://sub.example.com`은 별도 출처로 취급합니다. CDN처럼 화면 구성에 필요한 리소스가 다른 도메인에 있어도 브라우저 정책 및 캡처 성공 여부에 따라 결과가 달라집니다.

### 결과물에서 움직이는 것

- 좌측 메뉴: 페이지 제목·URL 목록, 텍스트 검색
- 페이지 이동: 메뉴 선택, 내부 링크 클릭, 앞/뒤 이동
- 본문 출력: `iframe.srcdoc`로 저장된 페이지 HTML을 표시
- 정적 보존 모드: 캡처 당시 DOM을 최대한 그대로 보여 주는 기본 모드
- **원본 JS 재생 (실험)**: 저장된 원본 스크립트 일부를 샌드박스에서 다시 실행하고, 일치하는 기록된 fetch/XHR 응답을 반환하며 WebSocket 수신 프레임을 시간순으로 흉내 냄

파일 자체는 하나이지만 페이지 전환·검색 등 **뷰어 동작에는 JavaScript가 필요**합니다. 스크립트를 꺼 놓은 브라우저에서도 모든 페이지를 편리하게 볼 수 있는 형태는 아닙니다.

### 무엇을 보존하지 못하나

- 서버 내부 DB, 서버 비즈니스 로직, 미수신 데이터, 미래의 실시간 상태
- DRM 원본, 보호된 브라우저 내부 상태, 접근 권한 없는 자료
- 모든 `Service Worker`·`IndexedDB`·iframe·Web Worker·브라우저 캐시 상태
- 로그인 인증 세션을 완전히 이동하는 기능
- 네트워크에 따라 반응하는 모든 SPA 라우팅, 동적 import, 결제·양식 제출의 실제 서버 동작
- 원본 화면의 픽셀 단위 동일성 및 모든 미디어의 완전 보존

아카이빙과 서버 복제는 다른 작업입니다. 이 프로젝트는 **관찰 가능한 브라우저 실행 결과를 로컬 문서로 최대한 보관**하는 쪽에 초점을 둡니다.

## 5. 다운로드와 빠른 저장

### 파일 후보 탐색의 작동 방식

현재 구현은 페이지의 DOM에서 파일로 보이는 링크, 다운로드 속성이 붙은 링크, 이미지, 미디어 URL을 추출합니다. **모든 네트워크 요청을 파일 후보 목록으로 보여 주는 범용 스니퍼는 아닙니다.** `blob:`, 일회성 접근 토큰, 특정 요청 헤더, 서버 측 인증 절차가 필요한 경우에는 직접 다운로드가 실패할 수 있습니다.

### 다운로드 상태 제어

목록은 Chrome의 `chrome.downloads.search`로 얻은 최근 기록을 바탕으로 만듭니다. 다운로드가 진행 중이면 정지/재개/취소, 완료되었으면 파일 보기를 요청합니다. 서버가 Range 재개를 지원하지 않거나 파일 상태가 달라지면 재개가 실패할 수 있습니다. 여러 파일을 선택한 경우 요청을 순차 제출하므로 **고성능 다중 연결 가속기**를 의미하지 않습니다.

### 로컬 텍스트 저장

텍스트를 내보내기 위해 Chrome Manifest V3의 offscreen document에서 Blob URL을 만들고, 다운로드 완료·중단 알림에 맞춰 URL을 해제합니다. `offscreen.html`과 `offscreen.js`는 이 작업에 사용됩니다.

## 6. GitHub 파일 생성

GitHub 기능은 **어디서든 선택한 텍스트를 특정 GitHub 저장소의 새 파일로 보존**하려는 요구를 위한 선택적 모듈입니다.

1. **✎ 빠른 메모** 탭에서 본문을 입력합니다.
2. `owner/repo`와 새 파일 경로(예: `ideas/2026-11-21-quick-note.md`)를 지정합니다.
3. GitHub Fine-grained PAT를 만들었다면 대상 저장소에만 **Contents: write**를 부여하고 일회성으로 입력합니다.
4. **저장소 조회** 또는 **폴더 탐색**으로 경로를 살펴볼 수 있습니다.
5. **GitHub에 새 파일 생성**을 누르면 GitHub Contents API의 PUT 요청으로 작성합니다.

토큰은 GitHub API 요청에 사용하며 **Chrome 로컬 설정에 저장하는 구현은 없습니다.** 대신 저장소 이름과 마지막 파일 경로는 기억할 수 있습니다. 다만 일회성 토큰도 입력한 동안 팝업 프로세스 메모리에 머물고, GitHub 연결을 통해 전송된다는 점은 알아두세요. 이름이 같은 파일은 자동 덮어쓰지 않으며, GitHub가 거절하면 오류를 보여 줍니다.

현재 GitHub 업로드 기능은 **텍스트 새 파일 생성 전용**입니다. 모든 형식의 바이너리 파일을 GitHub·Dropbox·Drive 등으로 전송하는 범용 업로더, 기존 파일 병합·수정, 폴더 트리 전체 관리까지 구현한 것은 아닙니다.

## 7. 구조와 처리 흐름

```text
loadit/
├── manifest.json               Chrome 확장 기능 및 권한 정의

├── capture.js                   CDP의 HTTP 응답·WebSocket 이벤트 기록
├── archive.js                   링크 탐색, DOM 스냅샷, 단일 HTML 조립
├── popup.html                   통합 팝업 마크업
├── popup.css                    팝업 스타일
├── popup.js                     다운로드/아카이브/메모 UI 이벤트
├── viewer.html                  최종 HTML 템플릿, 사이드바와 오프라인 재생기
├── offscreen.html               Blob URL 처리를 위한 숨겨진 문서
├── offscreen.js                 임시 Blob URL 생성/해제
├── test-site/
│   ├── index.html               DOM·fetch·XHR 기능 검증용 페이지
│   ├── page2.html               사이트 내부 이동·응답 검증용 페이지
│   └── site.css                 테스트 스타일
├── docs/
│   └── DEVELOPMENT_LOG.ko.md   장문 개발기·결정·한계·QA·로드맵
└── README.md
```

**모듈 관계:** `background.js`가 `capture.js`와 `archive.js`를 `importScripts`로 읽습니다. 팝업은 Chrome 메시지 API를 통해 작업을 요청합니다. `archive.js`는 각 페이지를 캡처한 뒤 `viewer.html`의 JSON 자리표시자를 데이터로 바꿔 하나의 HTML 문자열을 생성합니다. `offscreen.js`가 이를 Blob URL로 변환해 브라우저 다운로드 API에 전달합니다.

자세한 API/상태 흐름, 설계 선택 이유, 실패 사례, 작업 히스토리는 **[장문 개발기](docs/DEVELOPMENT_LOG.ko.md)**에 기록했습니다.

## 8. 권한·프라이버시·보안

| 권한 | 현재 용도 |
| --- | --- |
| `activeTab` / `tabs` | 현재 탭 주소 취득, 사이트 탐색용 임시 탭 열기·닫기 |
| `scripting` | 사용자 요청 시 페이지 DOM의 자산 후보 조사·스냅샷 실행 |
| `downloads` | 파일 다운로드 및 다운로드 상태·제어 |
| `storage` | UI 설정, 최근 선택 텍스트, 아카이브 진행 상태 |
| `contextMenus` | 링크·이미지·미디어·선택 텍스트의 우클릭 메뉴 |
| `offscreen` | Blob URL 생성 및 해제 |
| `debugger` | 사용자 요청 시 CDP Network/Page 관찰 |
| GitHub 호스트 권한 | GitHub 공식 REST API 이용 |
| 선택적 HTTP(S) 호스트 권한 | 지정 사이트의 페이지 캡처·순회 |

**중요:** 일부 민감 정보는 **의도적으로 자동 추출하지 않도록** 처리하지만, 이것이 아카이브 데이터 전체의 민감 정보 제거를 뜻하지는 않습니다. 예를 들어 네트워크 응답 본문·WebSocket 메시지·화면에 보이는 사용자 이름·일반 입력 필드에는 개인정보나 비밀이 포함될 수 있습니다. **저장한 HTML 자체를 비공개 자료로 간주하고 공유 전에 내용을 검토**하세요. 현재 아카이브는 암호화 보관함이 아닙니다.

원본 스크립트 재생은 선택 사항이며, 결과 파일의 격리된 iframe 안에서만 동작하도록 설계했습니다. 이 안전 경계가 모든 브라우저·모든 사이트에서 완벽하게 검증됐다고 주장하지 않습니다. 신뢰하지 않는 사이트의 아카이브는 실험 모드로 열지 않는 편이 좋습니다.

## 9. 제약과 알려진 문제

- **확장 서비스 워커 수명:** 장시간 캡처가 진행 중 브라우저의 서비스 워커 수명 정책에 영향을 받을 수 있습니다. 현재 강력한 영구 작업 큐·중단 복구 엔진은 없습니다.
- **CDP 디버거:** 다른 DevTools/디버거와 충돌하거나, 브라우저가 디버거 접근을 거절하면 캡처 범위가 줄어듭니다.
- **CORS와 자산 누락:** 이미지/스타일/폰트는 원격 서버 허용 여부에 따라 일부가 보존되지 않을 수 있습니다.
- **원본 JS 재생:** 기록된 API 요청에만 대응하며 같은 URL의 여러 응답/메서드가 복잡하게 얽힌 경우 원래 타이밍·행동과 달라질 수 있습니다.
- **단일 HTML 크기:** 페이지가 많거나 미디어가 크면 파일 크기가 급격히 증가합니다. 현재 크기 상한은 품질 보증이 아닌 작업 보호용입니다.
- **이미 저장된 파일의 무결성:** 암호학적 서명·자동 checksum 검증·아카이브 재현성 검사·중복 리소스 전역 dedupe는 완성되지 않았습니다.
- **파일 탐색 오탐/누락:** 파일처럼 보이는 링크만 찾으며 페이지 전체 트래픽을 다운로드 파일 목록으로 보여 주지는 못합니다.
- **실제 설치 동작:** 구현 코드 검토와 일부 브라우저 기반 분리 시험이 수행됐으나, Chrome 확장 전체의 사이트별 종단간 검증 및 대규모 호환성 수치는 확보되지 않았습니다.

### 고장 났을 때

- **확장이 로드되지 않음:** 압축 파일을 폴더처럼 선택하지 않았는지 확인하고, 확장 카드의 오류 메시지를 봅니다.
- **캡처가 실패함:** 페이지가 HTTP(S)인지, 호스트 권한이 허용됐는지, 다른 디버거가 붙어 있는지 확인합니다.
- **파일이 일부 비어 있음:** CORS, 인증, 파일 크기 제한, lazy loading, SPA/Service Worker 의존성을 확인합니다.
- **저장한 파일에서 원본 기능이 작동하지 않음:** 기본 정적 보존인지 실험적 JS 재생인지 구분하고, 누락된 응답이 있는지 확인합니다.
- **GitHub 저장 실패:** 토큰의 대상 저장소 범위, Contents 권한, 저장 경로의 기존 파일 여부, API 오류를 확인합니다.
- **다운로드 재개 실패:** 서버가 이어받기(Range) 지원을 제공하는지 확인합니다.

## 10. 테스트와 검증

저장소에 `test-site/index.html`, `page2.html`, `site.css`가 있습니다. 테스트 사이트를 HTTP(S)로 서비스한 뒤 Loadit으로 저장해 다음 항목을 확인할 수 있습니다. (테스트용 웹서버를 실행하는 방법은 개발 환경에 따라 다르며, **Loadit 자체에는 서버가 필요하지 않습니다**.)

- [ ] Chrome에서 확장 설치·팝업 3개 탭 정상 작동
- [ ] URL 파일 다운로드 및 우클릭 다운로드
- [ ] 파일 후보 탐색 → 다중 선택 다운로드
- [ ] 다운로드 정지·재개·취소 / 완료 파일 보기
- [ ] 선택 텍스트 로컬 저장 및 GitHub 새 파일 생성
- [ ] 첫 번째 페이지의 JS로 추가된 DOM이 정적 저장본에 보이는지 확인
- [ ] 두 번째 페이지가 **같은 HTML 안에서** 열리는지 확인
- [ ] 인터넷을 끊어도 목록·이미지·스타일이 가능한 범위에서 표시되는지 확인
- [ ] 수집된 fetch/XHR 응답이 실험 모드에서 재생되는지 확인
- [ ] WebSocket 수신 기록과 재생을 독립 테스트에서 확인
- [ ] 디버거 해제·임시 탭 정리·실패 시 자원 해제 확인
- [ ] 민감 정보 및 악성 HTML 입력에 대한 보안·회귀 테스트

**검증 완료로 표시한 항목이 아니라 앞으로 실제 Chrome에서 확인해야 할 체크리스트**입니다. 개발 과정에서 파일/문법/핵심 코드 경로와 GitHub 반영은 확인했고, 제한적인 브라우저 격리·메시지 전달 시험이 수행됐습니다. 실제 사이트별 캡처 성공률, 온전한 복원율, CPU·메모리·속도 수치는 측정하지 않았으므로 제시하지 않습니다.

## 11. 개발 원칙 및 기여

- **하나의 제품, 분리된 기능:** 다운로드·빠른 저장·아카이빙은 모듈을 나누고 UI만 통합합니다.
- **사용자가 시작하는 캡처:** 전체 사이트를 자동 무제한 수집하거나 비밀을 몰래 외부 서버에 보내지 않습니다.
- **단일 HTML 우선:** 복수 페이지 보존 결과는 가능하면 별도 서버나 폴더 없이 열 수 있는 한 파일로 만듭니다.
- **보존성과 실행성의 구분:** 원본 DOM 저장, 네트워크 기록, 실행 재현은 서로 다른 수준입니다.
- **완료와 검증은 구별:** 코드 작성·커밋·정적 검사·브라우저 실행·사용자 환경 검증은 각각 따로 기록합니다.
- **순수 웹 기술:** 소스 런타임은 HTML/CSS/JavaScript를 유지하고 불필요한 빌드 의존성을 피합니다.

문제 제보 시에는 브라우저 버전, 대상 사이트의 공개 테스트 URL(민감 URL 제외), 시작 URL 및 깊이/페이지 설정, 실제 동작과 기대 동작, 오류 메시지, 저장본의 민감정보 여부를 구분해 기록해 주세요.
